# 耐久モードの読みの修正

## 背景

今日の耐久のお題(`src/data/endurance.json`)の読みに、明らかな誤りが多い。
プレイヤーは読みのとおりに打たないと即終了になるため、誤った読みはそのまま「正しく打ったのにミス扱い」になる。
例: 「杜子春」が `としみつ`、「母も無い」が `はもない`、「二人暮しだ」が `にひとりくしだ`。

Claude Code が全7作品の `chunks` を読み、`docs/endurance-source/*.txt`(青空文庫のルビ付き原文)のルビと照らし合わせて、誤りを下の表にまとめた。

## 変更対象

触るファイル:

- `src/data/endurance.json` — 下の表のとおりに直す

触らないファイル:

- `src/game/**`・`worker/**`・`tests/**` — データだけの修正なので、ロジックとテストは変えない
- 文の `id` — 変えない

## 仕様

### 直し方

- 表の1行は、1つの文(`id`)の中の1つの区切り(`chunks` の1組)を表す
- 区切りの表記(`chunks[i][0]`)が「区切り」の列と一致するものを探し、読み(`chunks[i][1]`)を「正しい読み」に置き換える
- 同じ文の中で直したあと、その文の `reading` を `chunks` の読みをつなげたものに作り直す(`tests/endurance-data.test.ts` の "joins chunks back into text and reading" がこれを確かめる)
- 「表記も直す」の表は、`text` と `chunks[i][0]` の両方を直す
- 「オーナーが決めた読み」の表も、「読みの誤り」と同じように直す

## 受け入れ条件

- [ ] 表の「読みの誤り」の行がすべて直っている(表の行数は115)
- [ ] 「表記も直すもの」の2文が直っている
- [ ] 「オーナーが決めた読み」の9行が直っていて、「変えない」に挙げた区切りは変わっていない
- [ ] 文の `id`・文の数・作品の並びが変わっていない
- [ ] `npx tsc --noEmit` / `npm test` / `npm run build` / `npm run format:check` が通る

## 対象外

- 「市蔵」など、表に挙げていない「市」の読み
- 表にない文の表記と原文の細かな違い(句読点の位置など)
- 読み方を2通り受け付ける仕組み

## 想定される落とし穴

- `chunks` の表記に同じ文字列が2回出る文がある。表の区切りと完全に一致する組を直すこと
- 表で `正しい読み` が `今の読み` より長くなる行が多い。1作品の読みの合計が1200〜1800字に収まっているかは、`tests/endurance-data.test.ts` が確かめる。外れたら止めて聞く
- サーバー(`worker/ranking.ts`・`worker/stats.ts`)も同じ JSON を読む。修正を出したあとに、修正前の読みで遊んだ記録を入力ログから再計算すると合わなくなるおそれがある(未確認)。反映は Claude Code がデプロイのタイミングで判断するので、実装担当は気にしなくてよい
- JSON は UTF-8 のまま保つ。PowerShell のテキスト入出力で書き戻さない
